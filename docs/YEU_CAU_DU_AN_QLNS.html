🎯 1. Tổng quan & Mục tiêu Dự án

Dự án Quản Lý Nhân Sự (QLNS) nhằm xây dựng toàn bộ hệ thống quản trị nhân sự từ đầu với tiêu chuẩn hiện đại, tốc độ cao, khả năng mở rộng linh hoạt và trải nghiệm người dùng vượt trội.

🚀 Mục tiêu chính

Tối ưu hóa quy trình quản lý hồ sơ nhân viên, tự động hóa chấm công, tính lương, quản lý nghỉ phép và cung cấp hệ thống báo cáo KPI thông minh theo thời gian thực.

👥 Đối tượng sử dụng

Super Admin, Chuyên viên HR, Trưởng phòng/Quản lý bộ phận và toàn thể Nhân viên trong công ty.

📦 2. Phạm vi Công việc (Scope of Work)

Thành phần Công nghệ & Quy chuẩn Nội dung triển khai chi tiết
Backend Laravel 12, PHP 8.2+, MySQL 8.x • Xây dựng hệ thống API chuẩn (RESTful API): Phục vụ kết nối dữ liệu mượt mà với Frontend.
• Bảo mật đăng nhập (JWT Auth): Mã hóa token xác thực người dùng, tự động hết hạn & cấp mới an toàn.
• Mô hình mã nguồn chuẩn (Repository-Service Pattern): Tách biệt xử lý logic và dữ liệu, giúp dễ bảo trì & mở rộng.
• Kiểm soát dữ liệu đầu vào (Form Request Validation): Lọc và kiểm tra tính hợp lệ dữ liệu trước khi lưu vào máy chủ.
• Kiểm thử tự động (PHPUnit Tests): Viết script tự động test các tính năng cốt lõi để phòng tránh lỗi ngầm.
Frontend Vue 3, Vite, JavaScript (ES6+), Pinia • Lập trình giao diện hiện đại (Composition API): Giúp trang web chạy mượt, phản hồi tức thì không nháy trang.
• Quản lý trạng thái dữ liệu (Pinia): Lưu trữ tập trung thông tin đăng nhập, theme Dark/Light và trạng thái ứng dụng.
• Tối ưu tốc độ tải trang (Lazy Loading Routes): Người dùng mở đến màn hình nào hệ thống mới tải code màn hình đó.
• Bộ giao diện chuẩn hóa (Vuetify 3): Thiết kế thẩm mỹ cao, tương thích tốt trên cả máy tính và điện thoại.
• Kiểm thử giao diện (Vitest & Cypress): Đảm bảo các nút bấm, form nhập liệu hoạt động chính xác.
Database MySQL, Redis Cache • Thiết kế sơ đồ dữ liệu chuẩn (ERD): Đảm bảo cấu trúc dữ liệu khoa học, không trùng lặp.
• Quản lý phiên bản DB (Migrations & Seeders): Giúp tạo sẵn cấu trúc bảng và dữ liệu mẫu chỉ với 1 câu lệnh.
• Lưu vết lịch sử (Audit Logs): Tự động ghi nhận lại ai đã thêm, sửa hoặc xóa dữ liệu gì.
• Xóa mềm (Soft Deletes): Khi xóa dữ liệu sẽ đưa vào "thùng rác" để có thể khôi phục lại khi cần.
• Tối ưu truy vấn (Indexing & Redis Cache): Tìm kiếm danh sách hàng ngàn nhân viên trong chưa đầy 0.1 giây.
DevOps & CI/CD Docker, Nginx, GitHub Actions • Đóng gói ứng dụng (Docker Compose): Đóng gói trọn bộ Web, DB, Redis vào môi trường chuẩn hóa, chạy đồng nhất trên mọi máy.
• Xử lý hàng chờ ngầm (Laravel Horizon Queue): Gửi email, thông báo chạy ẩn bên dưới để không làm đơ trang web.
• Tự động hóa kiểm tra (GitHub Actions CI): Tự động chạy kiểm tra lỗi và phát hiện sự cố mỗi khi nhân sự nộp code mới.

📐 2.1 Quy chuẩn Cấu trúc Thư mục & Đặt tên (Dành cho Lập trình viên Junior)

💡 Lưu ý cho Junior Dev: Để dự án sạch sẽ và không bị rối code khi phát triển lên quy mô lớn, nhân sự phải tuân thủ nghiêm ngặt cấu trúc thư mục và quy tắc đặt tên tiêu chuẩn dưới đây:

📂 Cấu trúc Backend Laravel

• app/Http/Controllers/Api/v1/ - Nơi chứa Controllers (chỉ làm nhiệm vụ nhận/trả API).

• app/Services/ - Nơi xử lý toàn bộ logic nghiệp vụ chính (Business Logic).

• app/Repositories/ - Nơi viết các câu truy vấn cơ sở dữ liệu (Database Query).

• app/Http/Requests/ - Nơi viết kiểm tra dữ liệu đầu vào (Validation).

• app/Models/ - Nơi định nghĩa các bảng Eloquent Database.

📂 Cấu trúc Frontend Vue 3

• resources/js/views/ - Nơi chứa các màn hình trang web chính.

• resources/js/components/ - Nơi chứa linh kiện tái sử dụng (Modal, Table, Button).

• resources/js/stores/ - Nơi chứa Pinia Stores quản lý dữ liệu chung.

• resources/js/services/ - Nơi chứa file gọi API Axios sang Backend.

• resources/js/router/ - Nơi khai báo đường dẫn các trang web.

Đối tượng Quy tắc Đặt tên (Convention) Ví dụ Cụ thể
Đường dẫn API (URL) kebab-case (chữ thường, nối bằng dấu gạch ngang) /api/v1/employee-contracts, /api/v1/leave-requests
Bảng CSDL (MySQL Table) snake_case (dạng số nhiều, nối gạch dưới) employees, attendance_logs, payroll_details
File Model Laravel PascalCase (viết hoa chữ đầu, dạng số ít) Employee.php, AttendanceLog.php, PayrollDetail.php
File Controller Laravel PascalCase + từ Controller EmployeeController.php, AttendanceController.php
Component Vue 3 PascalCase (viết hoa các chữ cái đầu) EmployeeModalForm.vue, AttendanceTable.vue
Pinia Store (Vue 3) camelCase + tiền tố use...Store useEmployeeStore.js, useAttendanceStore.js

⚙️ 3.1 Yêu cầu Chức năng Backend (Laravel API)

STT Mô đun Chức năng Chi tiết Mô tả API & Xử lý Nghiệp vụ
1 Xác thực (Auth) Đăng nhập, Đăng xuất, Refresh Token (JWT), Quên mật khẩu qua email xác nhận OTP/Link.
2 Phân quyền (RBAC) Quản lý Role (Admin, HR, Manager, Employee) và Permission linh hoạt với Middleware kiểm tra.
3 Quản lý Nhân viên CRUD thông tin nhân viên, sơ yếu lý lịch, hợp đồng lao động, upload tệp tài liệu cá nhân.
4 Phòng ban & Cơ cấu Cơ cấu tổ chức hình cây (Tree structure), gán Trưởng phòng (Manager), luân chuyển nhân sự.
5 Chấm công & ca làm API ghi nhận Check-in/out (Wifi IP/GPS/QR Code), tổng hợp giờ làm, ca làm việc linh hoạt.
6 Quản lý Nghỉ phép Quy trình gửi đơn nghỉ phép, tính toán quỹ phép năm, luồng duyệt tự động theo cấp quản lý.
7 Tính lương (Payroll) Cấu hình công thức lương, phụ cấp, khấu trừ bảo hiểm/thế, tự động chốt bảng lương hàng tháng.
8 Báo cáo & Thống kê API tổng hợp số liệu nhân sự, biến động nhân sự, tỷ lệ đi làm/nghỉ phép, chi phí lương.
9 Thông báo Realtime Gửi thông báo qua WebSocket (Laravel Echo / Pusher) hoặc Email Queue khi có sự kiện duyệt đơn/lương.
10 Audit Log Tự động ghi lại vết mọi thao tác thêm/sửa/xóa dữ liệu quan trọng (User ID, IP, Old/New Data).

🚀 3.3 Quy trình 6 Bước Lập trình một Tính năng Mới (Junior Step-by-Step Workflow)

📌 Hướng dẫn thực hành cho Junior: Khi nhận yêu cầu làm bất kỳ một tính năng mới nào (ví dụ: *Tạo mới hợp đồng nhân viên*), lập trình viên phải thực hiện chuẩn xác theo **6 bước tuần tự** dưới đây:
  • Bước 1: Tạo DB Migration & Model (Backend)
    Chạy lệnh php artisan make:model EmployeeContract -m để tạo bảng trong Database. Định nghĩa rõ kiểu dữ liệu, các khóa ngoại (`foreignId`) và chỉ mục (`index`).
  • Bước 2: Tạo Form Request Validation (Backend)
    Chạy lệnh php artisan make:request StoreContractRequest để bắt buộc kiểm tra dữ liệu đầu vào (ví dụ: ngày bắt đầu hợp đồng không được để trống, lương không được âm).
  • Bước 3: Viết Logic ở Service & Repository (Backend)
    Viết hàm xử lý lưu hợp đồng vào `ContractService.php`. ⚠️ Tuyệt đối không viết trực tiếp logic dài dòng trong Controller! Bọc câu lệnh lưu trong DB::beginTransaction() để đảm bảo an toàn dữ liệu.
  • Bước 4: Khai báo Controller & API Route (Backend)
    Gọi `ContractService` trong `ContractController.php` và khai báo đường dẫn API trong file routes/api.php. Chạy PHPUnit test để đảm bảo API trả về JSON chuẩn HTTP Status 200/201.
  • Bước 5: Tạo API Service & Pinia Store (Frontend Vue 3)
    Tạo file contractService.js gọi API bằng Axios, và tạo useContractStore.js để lưu danh sách hợp đồng vào bộ nhớ Frontend.
  • Bước 6: Dựng Giao diện Component & Hiển thị Báo lỗi (Frontend Vue 3)
    Dựng màn hình form nhập liệu `ContractModal.vue`. Bắt buộc hiển thị rõ câu thông báo lỗi (Status 422) ngay dưới từng ô nhập nếu người dùng điền sai dữ liệu!

⚡ 4. Yêu cầu Phi Chức năng (Non-Functional Requirements)

⚡ Hiệu năng & Tốc độ

API response time < 300ms cho 95% request. Trang Vue render dưới 1s. Áp dụng Redis Caching triệt để.

🔒 Bảo mật (Security)

Tuân thủ chuẩn OWASP Top-10. JWT Expiration 1h + Refresh Token 7 ngày. Mã hóa bcrypt dữ liệu nhạy cảm.

📱 Khả năng Tương thích

Responsive 100% trên Desktop, Tablet và Mobile. Hỗ trợ Chrome, Safari, Edge, Firefox mới nhất.

🧪 Chất lượng Code & Test

Code Coverage ≥ 80% cho Backend Unit Tests. Định dạng code tuân thủ PSR-12 và ESLint / Prettier.

✅ 8. Tiêu chí Nghiệm thu (Acceptance Criteria)

⚠️ Lưu ý quan trọng: Sản phẩm chỉ được coi là hoàn thành khi vượt qua toàn bộ các tiêu chí bên dưới:

1. Chuẩn API & Đầy đủ Test

Tất cả 100% API tuân thủ RESTful standard, trả về JSON chuẩn và có PHPUnit test xanh 100% với coverage ≥ 80%.

2. UI/UX Chuẩn Thiết kế

Không xuất hiện lỗi Javascript ở console. Giao diện mượt mà, mượt cả trên thiết bị di động.
