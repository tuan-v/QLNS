### Ví dụ 1 luồng chạy thật: bấm "Thêm nhân viên"

Đi từ lúc bấm nút tới lúc bảng hiện nhân viên mới — chia rõ theo phía Frontend/Backend giống 2 bảng ở trên. Chú ý **4 chỗ có thể dừng sớm** (validate/quyền sai thì dừng ngay tại đó, không đi tiếp xuống các bước dưới).

Nhìn nhanh đường đi qua từng file (chi tiết từng bước ở danh sách bên dưới):

```
Frontend (trước khi gửi)
Employees.vue → EmployeeForm.vue → useEmployeeStore.js → employeeService.js → (gửi HTTP)

Backend (xử lý)
routes/api/v1/employees.php → Middleware (auth:api, permission:employee.create)
    → StoreEmployeeRequest → EmployeeController → EmployeeService
    → EmployeeRepository → Employee (Model) → EmployeeResource → (trả JSON)

Frontend (sau khi nhận response)
useEmployeeStore.js → EmployeeForm.vue (toast + đóng modal) → Employees.vue (gọi lại GET, làm mới bảng)
```

**Phía Frontend — trước khi gửi đi:**

1. `Employees.vue` — bấm nút "Nhân viên" → `openCreate()` → mở `EmployeeForm.vue` (modal trống, `employee = null`).
2. Người dùng điền form, bấm "Thêm mới" → `submit()` trong `EmployeeForm.vue`.
3. **[Dừng sớm #1]** `await formRef.value.validate()` — chạy toàn bộ `:rules` phía client (`notEmpty`, `isEmail`...). Sai thì dừng ngay tại đây, **chưa gửi request nào lên server** — verify bằng cách mở tab Network, bấm Lưu với form rỗng, thấy 0 request.
4. Hợp lệ → `store.create(payload)` (`useEmployeeStore.js`) → `employeeService.create()` → `axios.post('/api/v1/employees', payload)`.
5. Request rời trình duyệt. `bootstrap.js`'s interceptor tự gắn header `Authorization: Bearer <token>` + bật `useLoadingStore()` (thanh loading trên cùng chạy).

**Phía Backend — nhận và xử lý request:**

6. Laravel nhận tại `routes/api/v1/employees.php` — khớp route `POST /` → `EmployeeController::store`.
7. **[Dừng sớm #2]** Middleware `auth:api` kiểm tra token hợp lệ chưa → sai thì trả 401, dừng, **không tới Controller**.
8. **[Dừng sớm #3]** Middleware `permission:employee.create` kiểm tra quyền → sai thì trả 403, dừng.
9. **[Dừng sớm #4]** `StoreEmployeeRequest` tự động chạy validate (Laravel tự gọi trước khi vào hàm Controller, vì nó được khai làm tham số của `store()`) → sai thì trả 422 kèm `{"errors": {...}}`, dừng, **không tới Controller**.
10. Vào `EmployeeController::store()` — data đã chắc chắn hợp lệ. Gọi `EmployeeService::create($request->validated())`.
11. `EmployeeService::create()` — tự sinh mã `NV00x` (`generateCode()`), mở `DB::transaction()`, gọi `EmployeeRepository::create()`.
12. `EmployeeRepository::create()` → `Employee::create($data)` — Eloquent chỉ ghi những field có trong `$fillable` của `Employee.php`, field lạ (nếu có) bị bỏ qua.
13. `$employee` (Model vừa tạo) trả ngược lên Controller.
14. Controller bọc `new EmployeeResource($employee)` — bên trong tự `loadMissing(['department','position','manager','province','commune'])` rồi build JSON, người tạo không phải cấp dưới của ai nên không field nào bị ẩn.
15. `response()->json(..., 201)` — response rời Backend, quay lại trình duyệt.

**Phía Frontend — sau khi nhận response:**

16. `bootstrap.js`'s interceptor tắt loading bar. `store.create()` (Pinia) nhận response, trả về.
17. `submit()` trong `EmployeeForm.vue` chạy tiếp: `toast.success(...)`, `emit('saved')`, đóng modal.
18. `Employees.vue` nghe được `@saved="fetchData"` → gọi lại `GET /employees` (một vòng Frontend→Backend→Frontend khác, ngắn hơn — chỉ qua Route → Middleware → Controller → Service → Repository → Resource, không có Request vì `index()` không nhận input cần validate) → bảng hiện nhân viên mới.

Nhìn vào đây sẽ thấy: **càng dừng sớm càng tốt** — validate phía client (bước 3) đỡ tốn 1 lượt round-trip mạng, middleware (bước 7-8) đỡ tốn công chạy Service/Repository cho request không hợp lệ, FormRequest (bước 9) đỡ Controller phải tự viết lại kiểm tra input.

Đã sửa: bỏ tiêm `Request` qua constructor (dùng `request()` helper để luôn lấy đúng Request đang gắn trong container TẠI THỜI ĐIỂM gọi), và đổi cache từ cờ `bool` sang cache theo giá trị TOKEN đã giải mã — token đổi thì tự giải mã lại, token giữ nguyên thì vẫn tận dụng cache như cũ (không đổi hành vi/hiệu năng ở request thật). **Lỗi phát sinh thêm từ chính lần sửa trên** (phát hiện qua `/code-review`, 3 agent độc lập cùng báo): `setUser()` vẫn còn ghi vào property `resolved` cũ (đã bị xoá khi đổi sang cache theo token) — nghĩa là `Auth::guard('jwt')->setUser($user)` (chính là cách `actingAs()` của Laravel test hoạt động) bị **ghi vào chỗ chết, không có tác dụng gì**, lần gọi `user()` kế tiếp lại tự giải mã lại token thay vì dùng user vừa `setUser()`. Sửa: `setUser()` giờ set cả `$this->resolvedToken = $this->bearerToken() ?? '';` cùng lúc với `$this->user`, để cache khớp đúng token hiện tại |
